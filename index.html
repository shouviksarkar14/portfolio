Document intelligence

A 30-minute check, down to about a minute

Operations teams were reading long confirmation documents by hand and re-typing the fields into their systems. I designed an engine that reads the document, extracts the fields with a confidence score, and sends only the doubtful ones to a person.

How it was built
The call
Run the models on-premise. Clients would not send these documents to a cloud model, so the product had to work where the data already lived.
The design
Confidence-scored extraction with a human in the loop. Reviewers approve or fix only flagged fields, and their fixes feed the next round of prompt tuning.
The result
At one client a 30-minute check now takes about a minute at 90% accuracy, freeing ~480 hours a quarter. The same engine now runs at 6+ client institutions.
Rules over AI

Using AI only where rules run out

Clients sent order requests as free-text emails, and staff turned each one into an order by hand. The obvious move was to put AI on every email. Most emails were predictable, so I routed those through rules and kept AI for the messy remainder.

How it was built
The call
About 85% of requests go through rules and 15% through AI. Rules are cheaper, faster and easier to audit, and AI handles the requests rules can't parse.
Testing
Validated in user acceptance testing across 150+ orders from 8 client firms before go-live.
What went wrong
A data-residency requirement blocked rollout for one region and cost three weeks. The model was fine; the rollout plan had missed a compliance check, which now comes first.
The result
Client emails now become priced orders in production.
